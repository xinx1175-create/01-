# 模拟连续运行记录（合成行情，不是 OKX 数据）

§14 要求的「至少 1 小时实际运行记录」需要连上 OKX，开发环境的网络策略拦截了 `www.okx.com` 和 `ws.okx.com`，所以这里先用本地假交易所跑了一段长时间的连续运行，验证整条链路：预热、出分、信号事件、对照组、日报、经济数据日程、正常停止、回放一致。
**合成行情的涨跌是程序生成的，资金涌入时自带顺势漂移，下面的收益数字没有任何策略意义。**

## 运行方式

- 假交易所：`python -m flowmon sim --speed 150 --seed 3`，按 OKX 格式推 trades / books / open-interest / funding-rate / liquidation-orders，加速 150 倍
- 监控器：`config.example.toml` 原样（24 小时基准、15 秒桶、全部起步值），只把两个地址指向本地；日程文件里放了一条 `2026-10-05T12:30:00Z`
- 真实时间 2026-10-04 23:56 – 2026-10-05 00:12（16 分钟），模拟时间 **39.6 小时**（2026-10-05 00:07 → 2026-10-06 15:42 UTC）；最后用 SIGTERM 正常停止

## 结果

| 项目 | 数值 |
| --- | --- |
| 桶 | 9504 个，不完整 1 个（启动时的第一个桶，`startup`） |
| 第一个有效分数 | 2026-10-06 00:07:30，启动后 24.01 小时，与 24 小时预热一致 |
| 分数有效的桶 | 3742 个，分数范围 −96.2 到 96.3 |
| 信号事件 | 252 条（30 档 90、40 档 84、50 档 78），多空大致各半 |
| 对照组 | 15 条，预热结束后每小时 1 条 |
| 跟踪完整的事件 | 267 / 267 |
| 经济数据窗口 | 12:15–13:00 共 181 个桶标为 `calendar`（前 15 分钟到后 30 分钟） |
| 日报 | 2026-10-05 的日报在次日 00:30（模拟时间）自动生成 |
| 原始数据 | 约 150 MB（合成行情的成交频率不代表真实情况） |

回放核对：用实时写下的原始数据回放 38 小时、9189 个桶，与实时结果逐桶比对，**分数零差异**，实时已落盘的事件回放全部重现。

## 运行中发现的问题：「分数翻转」几乎一直成立

84 条 40 档信号里，83 条被 §8 的「30 分钟内正负翻转 3 次」标为不交易。原因是平静时分数在 0 附近小幅摆动（有效桶里 |S| < 5 的占一半以上），按规格原文，+0.3 变成 −0.2 也算一次翻转。已加开关 `conditions.flip_min_abs`（默认 0 = 按原文），要不要改请见 README「需要你确认的问题」第 4 条。
